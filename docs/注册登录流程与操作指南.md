# AWS Builder 账号注册与登录流程指南

本文档说明本项目中“网站注册 + 邮箱收码 + 登录验证”的实现原理与操作步骤，适用于日常运行和故障排查。

## 1. 总体流程

完整流程分为三段：

1. **注册阶段**
   - 打开 `https://builder.aws.com/start`
   - 点击 `Sign up with Builder ID`
   - 填写邮箱、姓名、注册验证码、密码
2. **注册后登录验证阶段**
   - 注册成功后自动进入登录校验逻辑
   - 输入同一邮箱和密码
   - 若触发登录二次验证（OTP），自动收码并提交
3. **结果落库阶段**
   - 账号写入 `accounts.jsonl`
   - 字段 `login_verified` 表示登录验证结果
   - `status=active` 表示注册+登录验证均通过

## 2. 邮箱收码原理

项目支持两种邮件来源：

- `email.provider=vps`：VPS 自建邮箱 API（`deploy/services/vps-email`）
- `email.provider=gmail_alias`：Gmail 别名（`base+tag@gmail.com`）+ IMAP 拉取验证码

当前推荐 `gmail_alias`，因为稳定性更好，且已支持：

- 注册验证码识别（`purpose=registration`）
- 登录验证码识别（`purpose=login`）
- 过滤模板占位码（例如 `555555`），优先提取真实验证码

核心模块：

- `src/services/gmail_alias_service.py`
- `src/helpers/builder_auth.py`
- `src/runners/main.py`

## 3. 临时邮箱网页：历史邮箱收码

页面文件：`deploy/services/vps-email/static/index.html`

当前已支持以下能力：

1. **历史邮箱列表**
   - 浏览器本地保存已创建邮箱（address + jwt）
   - 可在页面中切换历史邮箱继续查看验证码邮件
2. **导入历史 JWT**
   - 在新设备可粘贴旧 JWT 恢复历史邮箱
   - 页面通过 `/api/me` 解析 JWT 并恢复对应地址
3. **最新验证码展示**
   - 收件箱刷新时自动提取最近可用 6 位验证码并高亮显示

后端新增接口：

- `GET /api/me`（需 Bearer JWT）返回当前 JWT 对应邮箱地址

## 4. 关键配置

配置文件：`config/config.yaml`

```yaml
email:
  provider: gmail_alias
  gmail:
    base_user: your_gmail_user
    app_password: "xxxx xxxx xxxx xxxx"
    tag_length: 12

registration:
  verify_login_after_register: true
```

可用环境变量覆盖：

- `EMAIL_PROVIDER`
- `GMAIL_BASE_USER`
- `GMAIL_APP_PASSWORD`
- `VERIFY_LOGIN_AFTER_REGISTER`

## 5. 运行方式

### 5.1 一次完整验证（推荐）

```powershell
python deploy\_verify_mainpy.py
```

该脚本会自动：

- 上传最新代码到 VPS
- 重启代理/Xvfb
- 执行 `src/runners/main.py`
- 轮询日志并输出最终结果

### 5.2 只跑注册主流程

```powershell
python deploy\_run_gmail_alias_register.py
```

### 5.3 仅手动等待验证码（调试）

```powershell
python scripts\wait_gmail_code.py --email "your_alias@gmail.com" --purpose login
```

## 6. 成功判定

满足以下条件可判定账号可用：

1. `main.py` 日志出现：
   - `✅ 注册 + 登录验证均成功，账号可用`
2. `accounts.jsonl` 最新记录包含：
   - `"login_verified": true`
   - `"status": "active"`

VPS 默认路径：

- `/opt/aws-builder-id/accounts.jsonl`

## 7. 常见问题

### 7.1 注册成功但登录验证失败

重点检查：

- 是否触发了登录 OTP 页面（日志 `purpose=login`）
- 是否提取到真实验证码（非 `555555`）
- 登录页是否出现密码框/验证码框但未提交（看 `builder_auth` debug 输出）

### 7.2 临时邮箱页面切换历史邮箱失败

- JWT 可能过期或无效，重新创建邮箱并保存新 JWT
- 确认 API 可访问：`/api/health`

### 7.3 收不到验证码

- `gmail_alias`：检查 Gmail App Password 是否有效、IMAP 是否可登录
- `vps`：检查 MX 是否指向 VPS，`temp-email-api` 与 Postfix 是否正常

---

如需部署给他人使用，建议把代理信息、Gmail 凭据、SSH key 路径全部改为环境变量，不在仓库中硬编码。
